# MIND for DSH — UI 设计稿

> 状态：已实现，待用户验收
> 原则：极简、克制、只做浏览与配置；不复制 DSH 已有功能。

---

## 1. 入口

左侧栏 `sidebar.panellist`，位置在「插件」「自动化任务」之后，图标为线性 SVG（不用 emoji），文字「记忆」。

```
┌──────────────┐
│ 会话          │
│ 工作区        │
│ 插件          │
│ 自动化任务    │
│ 记忆          │  ← 新增
└──────────────┘
```

点击后打开 main 面板。

---

## 2. 主面板结构

左侧栏只有「记忆」入口；点击后**整个右侧大区域**就是 MIND UI。页面导航用顶部标签页，不再套一层左侧子导航。

```
┌────────────────────────────────────────────────────────────────────┐
│ 记忆   [时间线] [规则] [工作区] [提案 ②] [设置]                    │
├────────────────────────────────────────────────────────────────────┤
│  2026-10-19                                                        │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │ 09:12  修复注入竞态          2 turns                     ›  │  │
│  └──────────────────────────────────────────────────────────────┘  │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │ 08:40  迁移 hooks 验证       5 turns                     ›  │  │
│  └──────────────────────────────────────────────────────────────┘  │
│  ┌──────────────────────────────────────────────────────────────┐  │
│  │ 2026-10-18  设计评审          4 turns                     ›  │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                    │
│  （虚拟滚动；每页 50 条，滚动到底再取下一页）                      │
└────────────────────────────────────────────────────────────────────┘
```

- 时间线按天分组；每行 = `工作区名 - 日期` + 当日首个 turn 摘要（副标题）+ turn 数 + 箭头。
- 点击一行 → 在该行下方缩进 56px 内联展开，不再使用右侧分栏。
- 展开区列出该天的 turn；点击某个 turn → 原文继续在 turn 下方内联展开（分块加载）。
- 同一时间只展开一天；日期行和 turn 行都有展开/收起箭头。

## 3. 页面清单

### 3.1 时间线

- 按天倒序，keyset 分页（`cursor = (local_date, workspace_id)`，默认 50 条）。
- 顶部工作区选择器：全部工作区 / 单个工作区；使用 DSH `Menu` 原语（非原生 `<select>`），触发器占满可用宽度；切换时清空旧页并重置分页。
- 工作区显示名来自 DSH Workspace Registry 的 title；重命名会同步，自动标题 `default-workspace` 显示为「默认工作区」。
- 每行：`工作区名 - 日期`、当日首个 turn 摘要、turn 数、状态（未摘要/已摘要）；工作区名可省略，日期不截断。
- 不做 UI 搜索框；检索由模型通过 `mind_search` 使用，UI 只负责按时间/规则浏览。
- 空态：「还没有记忆。开始一轮对话就会自动记录。」

### 3.2 规则

- 只有**项目级长期规则**，每条挂在具体工作区；不存在全局规则、项目笔记或白板。
- 每条：标题 + 一句结论 + 版本号 + 所属项目 + 更新时间。
- 点击条目打开结构化编辑表单（方案 B+）：
  - 标题：单行输入
  - 项目：工作区单选（必选）
  - 内容：多行文本，带「编辑 / 预览」切换，预览用 Markdown 渲染
  - 状态：启用 / 停用
- 保存后版本 +1；编辑是整条替换，不做字段级合并。
- 只显示已批准规则；未批准的在「提案」页。

### 3.3 工作区

- 表格：名称 / 当前路径 / inode / 最后出现 / 置信度 / DSH 映射。
- 路径用等宽字体；过长的路径中间省略，悬停显示全路径。
- 只提供「复制 workspace id」，不做删除/合并（危险操作留给后续）。

### 3.4 提案

- 待审列表：标题、内容、来源 turn（可点开原文）、提出时间。
- 操作：批准 / 拒绝。
- 批准后成为该工作区的规则，进入「规则」并参与下一轮注入。
- 空态：「没有待审提案。」

### 3.5 设置

- 捕获开关、注入开关。
- 规范目录（只读展示路径 + "在 Finder 中打开"）。
- 动态快照预算（字符数）。
- 时间轴保留天数（默认 30）。
- 迁移导入：v1 置灰，标注「后置」。

## 4. 内联展开

不使用右侧分栏。展开内容直接出现在被点击行下方：

```
▶ 2026-10-19  AI助手自我介绍                 2 turns  ⌄
    └─ 15:41  AI助手自我介绍                         ⌄
          本轮仅介绍助手身份与能力……
          15:42  查询2026年10月19日A股收盘行情            ⌄
                 本轮结论……
                 ┌───────────────────────────────┐
                 │ # Turn ...                     │
                 │ ## 用户                        │
                 │ ...                            │
                 │ [加载更多]                      │
                 └───────────────────────────────┘
▶ 2026-10-18  插件骨架                        1 turn   ⌄
```

- 外层缩进 56px；turn 行用 16px 圆角高亮，日期行用 20px 圆角高亮（与官方插件卡片一致）。
- 不使用硬竖线；层级用缩进、圆角高亮和细分隔横线表达。
- 原文按 20K 字符分块；「加载更多」使用 `next` 偏移。
- 底部显示 `已加载 / total 字符`，不自动全量加载。

## 5. 交互与内存约束（硬要求）

1. **历史列表 keyset 分页**：时间线默认 50 天/页；其余列表有硬上限（当天 turns 300、规则 500、提案 200、工作区 200），并返回 `truncated`。
2. **虚拟滚动**：只渲染可视区 + 缓冲区。
3. **详情按需加载**：点击才请求；原文按 20K 字符分块。
4. **禁止全量接口**：每个读接口都有上限，不存在「返回全部历史」的 API。
5. **切换页面不保留旧列表 DOM**（离开即销毁）。
6. 时间线在 1000+ 条时保持流畅滚动。

---

## 6. Host ↔ Client API（草案）

| API | 说明 |
|---|---|
| `mind_timeline_page({cursor?, limit?})` | 返回天列表 + nextCursor |
| `mind_day({date})` | 某天的 turn 列表（标题/结论/指针） |
| `mind_turn({turnId, offset, max})` | 原文分块 |
| `mind_current()` | 已批准的项目规则 |
| `mind_workspaces()` | 身份、路径、inode、置信度 |
| `mind_proposals({status})` | 提案列表 |
| `mind_resolve_proposal({id, action})` | 批准/拒绝 |
| `mind_settings()` / `mind_update_settings()` | 读取/更新配置 |

## 7. 视觉规范

- 复用 DSH 官方 UI primitives；不引入新的设计语言。
- 中性色背景；一个强调色（仅用于主操作）。
- 无渐变、无玻璃拟态、无彩色描边卡片、无 emoji 图标。
- 列表行高 36px；路径/ID 用等宽字体。
- 只做必要动效（列表展开/收起），不做装饰动画。
- 空态、加载态、错误态三态齐全；错误必须显示可读原因。

---

## 8. 验收标准

1. 时间线 1000+ 条滚动流畅，无全量请求（网络面板可证）。
2. 重命名工作区后，「工作区」页显示新路径，记忆归属不变。
3. 提案批准后，下一轮注入包含该规则。
4. 原文超过 50KB 时可分块读完。
5. 1280px 宽度下无横向滚动。
6. 空库、单条、1000 条三种状态都正常。
7. 没有聊天、图谱、日历等多余功能。

自测记录（2026-10-19，隔离 DSH Web）：

- 292 天数据：首屏 DOM 只渲染 22 行；每次滚到底只请求一页 50 天，cursor 单调；DOM 行数保持约 26。
- 未登录请求返回 401；原文 `offset=0&max=16` 返回 16 字符与 `next=16`。
- 提案批准、条目编辑（版本 +1）、禁用后不注入、设置持久化均通过。
- 浏览器控制台无错误。
